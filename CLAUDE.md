# Next Up

Walk-in check-in and queue system for barber shops, replacing the paper sign-in pad. Open source and self-hosted: each install is one business (one or more locations) with its own name, colours and logo set from the admin Branding tab. It started as the in-house system for Barber on George, which now runs the generic release with its own branding; nothing in the code should be specific to one shop. See [README.md](README.md) for the full user-facing docs, Docker setup, and VPS deployment.

## What it does

Each shop runs four kinds of screen, all kept in sync live over Socket.IO:

| Screen | Route | Who uses it | Auth |
|---|---|---|---|
| Kiosk | `/kiosk/<slug>/<kiosk_token>` | Customers on the shop tablet: enter name, optionally pick an on-duty barber | Bearer token in URL |
| Display | `/display/<slug>/<display_token>` | TV in the shop: read-only "in the chair" and "waiting" lists | Bearer token in URL |
| Staff | `/staff/<slug>` | Barbers (phone or tablet): call next customer, mark done, remove no-shows | Flask-Login |
| Admin | `/admin/`, `/admin/metrics` | Shop owner: manage locations, barber logins, device links, timezone, view charts | Flask-Login + `is_admin` |

Customer flow: kiosk check-in creates a `QueueEntry` (`waiting`), a barber calls them (`in_progress`), then completes (`done`) or removes them as a no-show (`cancelled`). For `UNDO_WINDOW` (10 min) after Complete/Remove, the staff dashboard's Recently Finished list can undo it (`done` back to `in_progress`, `cancelled` back to `waiting`); `removed_at` exists only to time that window. The list comes from `staff_queue_state()` and is never sent to the display.

## Stack

- Python 3.12, Flask app factory (`create_app` in [app/__init__.py](app/__init__.py)), one blueprint per screen
- Flask-SQLAlchemy + Flask-Migrate (Alembic migrations in [migrations/](migrations/)), PostgreSQL 16 in production
- Flask-SocketIO in **threading** mode (`simple-websocket`, no eventlet/gevent), socket path `/updates`
- Flask-Login for barber/admin sessions
- Server-rendered Jinja templates and vanilla JS in [app/static/js/](app/static/js/). No Node, no frontend build step.
- Docker Compose (app on Gunicorn + Postgres). Gunicorn must stay at **one worker** (`-k gthread -w 1 --threads 8`) because Socket.IO has no message queue to share broadcasts across processes.

## Code map

- [app/models.py](app/models.py): `Location`, `OpeningHours` / `SpecialHours`, `Barber` (the login model, also admins), `QueueEntry`, `Setting` (key/value: `timezone`, branding, the Getting Started hide flag), `BrandAsset` (uploaded logo/icon PNGs)
- [app/branding.py](app/branding.py): shop name, dark/accent colours (contrast-checked against white), logo and icon. `get_brand()` is injected into every template as `brand`; `_brand_head.html` turns it into CSS variables and favicon links. Uploads are re-encoded as PNG by Pillow; `/brand/icon-<size>.png` and `/favicon.ico` are rendered from the icon, else the logo, else a built-in mark. Every change bumps `brand_version` and calls `notify_screens()`.
- [app/sockets.py](app/sockets.py): `queue_state` / `broadcast_queue` and `on_duty_state` / `broadcast_barbers`, the `join` handler that gates room access, and the in-memory registry of connected kiosk/TV screens (`device_status`, `disconnect_devices`)
- [app/audit.py](app/audit.py): activity log covering every action the app can produce, not just admin ones (`audit.record(action, summary, category=...)`; `automatic=True` for changes the app makes itself, no request context for CLI, no logged-in actor for a kiosk check-in - each of those overrides `category` too; `actor_name=` for a non-user actor like `UNKNOWN_ACTOR` on failed logins keeps it), shown filterable (by category/event/who/date) on the admin Activity tab
- [app/kiosk.py](app/kiosk.py), [app/display.py](app/display.py): token-protected device pages. A check-in can be a group (one `customer_name` per person, up to `MAX_GROUP_SIZE`): separate `QueueEntry` rows sharing `checked_in_at` and the preferred barber, so the queue orders ties by id. A kiosk check-in POST always redirects (Post/Redirect/Get), with the "You're checked in" details carried once in the session, so a screen reload can never resubmit it. `kiosk.js` clears a form left idle for a minute.
- [app/staff.py](app/staff.py): location picker, dashboard, call/complete/remove actions, on-duty tracking
- [app/admin.py](app/admin.py): locations, barbers, password resets, token regeneration, settings
- [app/metrics.py](app/metrics.py): admin charts (cuts per day/barber/location, busiest-times heatmap, wait and service times) and the visits CSV export (`/admin/metrics/visits.csv`). PDF is the browser's print of the metrics page (print styles at the end of `brand.css`). Export values go through `_csv_safe` because customer names come from the public kiosk.
- [app/web_app.py](app/web_app.py): web app manifests for adding the staff pages (`/staff/app.webmanifest`, linked from `base.html`) and each kiosk (`/kiosk/<slug>/<token>/manifest.webmanifest`, token-protected because its start URL is the secret link) to a home screen. Manifests are fetched without cookies, so they must not need a login.
- [app/auth.py](app/auth.py): login, logout, forced password change
- [app/authz.py](app/authz.py): `admin_required` decorator
- [app/opening_hours.py](app/opening_hours.py): automatic opening hours (schedule maths, the manual-hold rule, the background check) and the admin page `admin/location_hours.html` served from [app/admin.py](app/admin.py)
- [app/announcements.py](app/announcements.py): the per-location announcement on the TV and kiosk (`Location.announcement`), set by barbers (staff dashboard) and admins (Locations tab) through `set_announcement()`, which broadcasts and logs it. Every announcement ends at local midnight (`announcement_until`); `current_announcement()` hides an expired one, and the queue-cleanup thread clears it and broadcasts. TV and kiosk update it live via `announcement.js`, always with `textContent`
- [app/queue_cleanup.py](app/queue_cleanup.py): nightly clear of customers left in a queue from before today (waiting become no-shows; in the chair become done with `completed_at = called_at`, which `QueueEntry.has_chair_time` keeps out of chair-time metrics)
- [app/background.py](app/background.py): `start_background_checks` starts the off-duty, opening-hours and queue-cleanup threads
- [app/settings.py](app/settings.py): shop timezone (until an admin picks one, `Config.DEFAULT_TIMEZONE` from the `TIMEZONE` env var, else UTC; tests use `Australia/Hobart` for its daylight saving), used by metrics for day/hour bucketing
- [app/auth.py](app/auth.py) `setup()`: the first-run `/setup` page where the owner creates the first admin login. `/` and `/login` redirect there while no login exists (`needs_first_admin()`), and it closes once any does. A `Setting` row (`SETUP_CLAIM_KEY`) inserted in the same transaction stops two simultaneous submissions both succeeding.
- [app/cli.py](app/cli.py): `flask bootstrap` (first-run: only creates an `admin` login if `ADMIN_PASSWORD` is set, otherwise prints a pointer to the browser; never creates locations), `flask seed-demo` (fills an empty database with the made-up shop in [app/demo.py](app/demo.py), used for trying it out and for the docs screenshots), `flask set-branding`, and `flask reset-admin-password` (lockout recovery)
- `setup_steps()` in [app/admin.py](app/admin.py): the Getting Started checklist on the admin page for a new install. An admin with no locations lands there from `staff.landing`. Its devices step (a kiosk and a TV have each connected) is also ticked live by `device-status.js`, from the `state` in each `device_status_update()`.
- [docker/entrypoint.sh](docker/entrypoint.sh): generates/persists `SECRET_KEY`, waits for Postgres, runs `flask db upgrade` then `flask bootstrap`

## Key concepts and gotchas

- **Device tokens are the access control** for kiosk and display. There is nobody to log in on that hardware, so each `Location` has a random `kiosk_token` and `display_token` in the URL. Compare them with `secrets.compare_digest`. Admins can regenerate them, which instantly breaks the old link. The Socket.IO `join` handler enforces the same rule (valid display/kiosk token or an authenticated session).
- **Any state change must broadcast.** After committing a queue change call `broadcast_queue(location)`; after an on-duty change call `broadcast_barbers(location)`. Each location has three rooms (helpers in `app/sockets.py`): `location-<slug>` (every screen, barber roster), `location-<slug>-staff` (queue with full names) and `location-<slug>-display` (queue with names shortened by `shorten_name`, "Jordan S."). The kiosk joins only the first. Never send full customer names to the display room.
- **Default vs on-duty location.** `Barber.default_location_id` only pre-selects the login picker. `on_duty_location_id` is where they are actually working (set on reaching a dashboard, cleared on logout) and drives the kiosk's preferred-barber list. Any barber can work any location. Barbers with `show_on_kiosk=False` (set by an admin) or `on_break=True` (set by the barber from their dashboard, cleared by `clear_on_duty`) can work the queue but don't appear on the kiosk; use `kiosk_barbers()` in [app/sockets.py](app/sockets.py) as the single source for that list.
- **Forced password change.** `must_change_password` is set for new accounts and admin resets; a `before_request` hook in [app/__init__.py](app/__init__.py) redirects those users to `/change-password`.
- **Logins are server-side sessions** ([app/login_sessions.py](app/login_sessions.py)). Each login gets a `LoginSession` row, and the signed Flask cookie only carries its random token. `load_user` rejects the request unless the row exists, has been active within `PERMANENT_SESSION_LIFETIME` (12h idle), and the barber is active. Log people in with `start_session()` (never `login_user` directly) and end sessions with `end_current_session()` / `end_all_sessions()`. Password resets, deactivation and admin "Log Out" all call `end_all_sessions`. Admin "Log In" (`put_barber_on_duty`) only sets `on_duty_location_id` and creates no session. [app/off_duty.py](app/off_duty.py) runs a background thread (every `OFF_DUTY_CHECK_SECONDS`, 0 in tests) that takes off duty anyone with no live session who has been on duty (`on_duty_since`) longer than the session lifetime, which covers both admin logins and phone logins that went idle. It starts (via `start_background_checks` in [app/background.py](app/background.py), with the opening-hours thread) on the first web request or Socket.IO join, never in `create_app`, so CLI commands don't start it.
- **CSRF (Flask-WTF) covers every POST.** Any new `<form method="post">` needs `<input type="hidden" name="csrf_token" value="{{ csrf_token() }}">` (a test scans all templates for this). JS-built forms read the token from `<meta name="csrf-token">` in `base.html` (see `staff.js`). Logout is POST-only. `TestConfig` disables CSRF; [tests/test_csrf.py](tests/test_csrf.py) turns it back on.
- **Login rate limiting** is in [app/login_throttle.py](app/login_throttle.py): failures are stored in `login_attempts`, and a login is refused (429) once the username has 5 or the IP has 20 failures within 15 minutes. Limits come from `LOGIN_*` config. Set `BEHIND_PROXY=true` behind a reverse proxy (enables `ProxyFix`) or every visitor shares the proxy's IP.
- **Log every action worth an audit trail.** Any new admin/CLI action that changes something should call `audit.record("thing.verb", "Plain-English summary")` (defaults to `category="admin"`) after it succeeds, and not when it's refused. Barber queue/dashboard actions pass `category=audit.CATEGORY_BARBER`; customer check-ins and automatic/CLI actions get their category inferred automatically. [tests/test_audit.py](tests/test_audit.py) checks the wording.
- **Opening hours.** With `Location.auto_hours` on, a background thread (every `OPENING_HOURS_CHECK_SECONDS`, 0 in tests) sets `Location.closed` from `OpeningHours` (per weekday) and `SpecialHours` (per date, overriding the weekday), less `checkin_cutoff_minutes`, broadcasting and logging each change as automatic. A manual Open/Close must go through `set_store_closed()`: when it disagrees with the schedule it sets `manual_until` to the next scheduled change or local midnight, whichever is first, and the thread leaves the store alone until then. Schedule functions take an explicit `now`; tests patch `app.opening_hours.utcnow` for routes. Kiosk and staff pages reload on `store_status`, so text like "Back Tuesday at 9:00 am" is rendered server-side and never says "tomorrow".
- **Screen connection status** comes from `_device_connections` in `app/sockets.py` (Socket.IO sid to location and kiosk/display), which is only correct because the app runs as one process. `Location.kiosk_last_seen_at` / `display_last_seen_at` record the last connect or disconnect. A screen still counts as online for `RECONNECT_GRACE` (10s) after it drops off (kiosks reconnect on every check-in). One last seen before the app started is `unknown` (a restart records no disconnects) until it reconnects or `STARTUP_GRACE` (60s) runs out; the staff kiosk note treats unknown as not offline. A screen that vanishes without closing its connection is only noticed by Socket.IO's ping (`ping_interval` / `ping_timeout` on `SocketIO` in [app/__init__.py](app/__init__.py)). `device_status()` includes `offline_in` (seconds left of that grace), since nothing happens server-side when it runs out: live pages time it themselves. The staff dashboard's "The kiosk isn't connected" note comes from `kiosk_status()`, pushed to the staff room on every kiosk connect/disconnect. The admin Device Links tab is live too: `device-status.js` sends `watch_devices` (admins only; joins `ADMIN_DEVICES_ROOM`, acknowledged with every location's status, and re-sent on reconnect and when a grace ends), and every screen connect/disconnect pushes `device_status_update()`, whose HTML comes from the same macro as the page ([admin/_device_status.html](app/templates/admin/_device_status.html)). Anything that invalidates a device link must call `disconnect_devices()`, or screens on the old link keep receiving live updates.
- **Branding is never hard-coded.** Use `brand.name` in templates (`get_brand().name` in Python) and the `--brand-*` / `--color-*` CSS variables (no hex colours in CSS or JS for brand uses; `--color-danger*` is the fixed red for warnings). Brand images come from `brand.*_url` / `brand.icon_url(size)`, never `static/images`.
- **App version and auto-reload.** `compute_app_version()` hashes everything under `app/` at startup. It's added as `?v=` to every static URL. The screen version, `screen_version()` in [app/branding.py](app/branding.py) (code version plus `brand_version`), is `window.APP_VERSION` and the Socket.IO `join` acknowledgement, and is pushed as `app_version` to every location room on a branding change. Kiosk, display and staff pages pass both to `checkAppVersion` ([app/static/js/app-version.js](app/static/js/app-version.js)) and reload when it differs from `window.APP_VERSION`. They also call `watchConnection(socket)` ([app/static/js/connection-status.js](app/static/js/connection-status.js)) to show the "Connection lost" banner from `_connection_banner.html` while disconnected. Any new long-running screen should do the same.
- **Screen wake lock.** Kiosk and display load [app/static/js/wake-lock.js](app/static/js/wake-lock.js), which holds a Screen Wake Lock and re-requests it when the page becomes visible again or on the next tap (the browser drops it whenever the page is hidden). It needs HTTPS and silently does nothing without it. Staff pages deliberately don't load it, so barbers' phones can sleep.
- `SESSION_COOKIE_SECURE` defaults to true, so plain-HTTP deployments must set it to false in `.env`.
- The test `app` fixture holds one app context for the whole test, so [tests/conftest.py](tests/conftest.py) clears Flask-Login's `g._login_user` and Flask-WTF's `g.csrf_token` before each request. Multi-device tests use separate `app.test_client()` instances.
- Timestamps are stored timezone-aware in UTC (`utcnow()` in models); convert with `get_timezone()` for display and metrics.
- `pytest.ini` turns every warning into a test failure. Fix new warnings at the source; only add an `ignore::` filter for one you can't fix.
- Schema changes need an Alembic migration (`flask db migrate -m "..."`), since production runs `flask db upgrade` on every start.

## Running and testing

```bash
docker compose up -d --build                   # app on http://localhost:8000
# then open the app in a browser to create the admin login
docker compose exec app python -m pytest       # tests
```

Tests in [tests/](tests/) use `config.TestConfig` with in-memory SQLite, so they never touch Postgres. Fixtures in [tests/conftest.py](tests/conftest.py) provide `app`, `client`, `locations`, and `barber`.

For local dev without Docker: set `DATABASE_URL`, then `python wsgi.py` (port 5000, debug).

## Documentation site

[docs/](docs/) is the user-facing site (Jekyll, published by GitHub Pages from `/docs`; see [docs/README.md](docs/README.md)). Screenshots and the demo video are generated, never edited by hand: [docs/tools/build-media.sh](docs/tools/build-media.sh) runs the app in Docker with `flask seed-demo` and [docs/tools/capture.py](docs/tools/capture.py) drives it with Playwright. When a change alters how a screen looks or behaves, update the matching guide and re-run the script. Write the guides plainly for shop owners and barbers: no em dashes, no marketing language.
